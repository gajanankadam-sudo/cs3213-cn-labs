Practical 1 · Unit I · CO1

Digital line encoding

Aim: Implement Unipolar NRZ, Polar NRZ, NRZ-Inverted, Bipolar, Manchester and Differential Manchester encoding and compare the resulting signals.

Theory

Line coding maps a bit stream to voltage levels on the wire. NRZ schemes hold one level for the whole bit, so long runs of identical bits give no transitions and the receiver's clock drifts. Biphase schemes (Manchester, Differential Manchester) force a transition in the middle of every bit, which makes them self-clocking at the cost of twice the signal rate. Bipolar AMI sends 0 as zero volts and alternates the polarity of 1s, which removes the DC component.

Conventions used here: Polar NRZ-L sends 1 as +V and 0 as −V. NRZ-I starts at −V and inverts on every 1. Manchester follows IEEE 802.3 (0 = high→low, 1 = low→high). Differential Manchester has a transition at the start of a bit for 0 and none for 1, starting from +V.

Enter at least one 0 or 1.

Viva questions
  1. Why does Manchester encoding need twice the bandwidth of NRZ?
  2. Which of these schemes have no DC component for any input? Check the DC column.
  3. What problem does NRZ-I solve over NRZ-L, and which input still breaks it?
  4. Which Ethernet standard uses Manchester encoding, and what replaced it at higher speeds?

Small LAN, network commands and switch port VLANs

Aim: Set up a four-computer LAN on a switch, assign unique IP addresses, practise ping, ipconfig, arp, netstat, nbtstat, nslookup, route, tracert, pathping and nmap, and assign switch ports to VLANs.

Theory

Each PC gets a unique address in 192.168.1.0/24 with R1 (192.168.1.1) as default gateway. Before the first ping to a local host, the PC sends an ARP request to learn the MAC address; the entry then appears in arp -a. A switch forwards frames only between ports in the same VLAN, so two PCs on different VLANs cannot reach each other even on the same subnet. Here R1's port Fa0/24 is in VLAN 1, so only VLAN 1 hosts reach the gateway and the Internet.

Practical 3 · Unit II · CO2
  
Error detection and correction: Hamming code and CRC

  
Aim: Encode a 7/8-bit ASCII character with a Hamming code or CRC, inject bit errors in the channel, and detect or correct them at the receiver. Extend to the CRC-32 FCS used by Ethernet.

  
Theory

    
Hamming code: for m data bits choose r parity bits with 2r ≥ m + r + 1, placed at positions 1, 2, 4, 8. Each parity bit gives even parity over the positions whose index has that bit set. At the receiver, XOR of the positions of all 1-bits is the syndrome. Syndrome 0 means no error; otherwise it is the position of the single flipped bit.

    
CRC: append r zeros (r = degree of the generator) and divide by the generator using mod-2 (XOR) division. The remainder is the CRC and is appended to the data. The receiver divides the whole codeword; a non-zero remainder means an error. Ethernet uses CRC-32 (0x04C11DB7) as its Frame Check Sequence.

Practical 4 · Unit II · CO2
  
Sliding window: Go-Back-N and Selective Repeat

  
Aim: Simulate Go-Back-N and Selective Repeat ARQ in peer-to-peer mode and observe how each recovers from lost frames and lost acknowledgements.

  
Theory

    
Go-Back-N: the sender may have N unacknowledged frames in flight and keeps one timer for the oldest. The receiver accepts only the next in-order frame and sends cumulative ACKs (ACK n = all frames up to n received). On timeout the sender resends every outstanding frame. With m-bit sequence numbers, N ≤ 2m − 1.

    
Selective Repeat: each frame has its own timer and the receiver buffers out-of-order frames inside its window, acknowledging each one individually. Only the lost frame is resent. N ≤ 2m−1.

    Practical 5 · Unit IV · CO4
  
    Dynamic routing with single-area OSPFv2
    
  
    Aim: Deploy OSPFv2 in area 0 across six routers, observe the shortest-path tree computed by each router, and see how link failures and the reference bandwidth change the routes.
    
  
    Theory
    
    
    OSPF is a link-state protocol. Every router floods LSAs describing its links, builds the same link-state database, and runs Dijkstra's SPF algorithm with itself as root. Interface cost = reference bandwidth ÷ interface bandwidth (minimum 1). With the default reference of 100 Mbps, FastEthernet and Gigabit links both cost 1, which is why auto-cost reference-bandwidth is raised on modern networks.

    Practical 7 · Unit V · CO5
  
    UDP file transfer
    
  
    Aim: Transfer a script, text, audio and video file between two machines with UDP sockets and analyse what happens when datagrams are lost.
    
  
    Theory
    
    
    UDP has no connection setup, acknowledgements or retransmission: socket() → bind() on the receiver, then sendto()/recvfrom(). Each datagram here carries a 4-byte application sequence number so the receiver can detect gaps. Adding acknowledgement and retransmission in the application (as TFTP does) restores reliability at the cost of extra traffic.

    Protocol stack: Ethernet, IP, TCP and UDP packet formats
    
  
    Aim: Generate a custom packet, inspect every header field the way Wireshark dissects it, and see how checksums, padding and the FCS are computed.
    
  
    Theory
    
    
    An Ethernet II frame carries a 14-byte header (destination MAC, source MAC, EtherType) and a 4-byte FCS. Frames shorter than 64 bytes are padded. The IPv4 header (20 bytes without options) has its own checksum. TCP and UDP checksums cover a pseudo-header (source IP, destination IP, protocol, length) plus the segment.     Practical 9 · Unit VI · CO6
  
    HTTP/1.0, 1.1 and 2.0 behaviour with success and error codes
    
  
    Aim: Compare how each HTTP version loads a page with embedded objects and inspect requests and responses for success, redirection, client-error and server-error status codes.
    
  
    Theory
    
    
    HTTP/1.0 opens a new TCP connection for every object (2 RTT each). HTTP/1.1 keeps the connection open (persistent) and allows pipelining: several requests sent without waiting, but responses must return in order, so one large object blocks the rest (head-of-line blocking). HTTP/2 multiplexes many streams over one connection as binary frames, so a large object no longer blocks small ones.
    
    
    There is no published HTTP/1.2 standard. The "1.2" in the syllabus is shown here as HTTP/1.1 with pipelining, the step between 1.1 and 2.0.
