How this lab works

You write each program in Java or C++ on the lab machine. This page gives you the specification, starter code with TODO markers, and test input. You run your program on that input and paste its output back here to be checked line by line.

  1. Copy the starter code for your language into a file with the name shown.
  2. Complete every TODO. Do not change the input and output format: the checker compares text exactly (extra spaces and blank lines are ignored).
  3. Copy the test input into input.txt, then run, for example: java LineEncoding < input.txt > output.txt or ./line_encoding < input.txt > output.txt.
  4. Paste output.txt into the checker and press Check. Fix and repeat until every line matches.
  5. Press "New test set" and pass that too. Your faculty may give you a set number to use; type it in the set box.

Socket practicals (P6, P7, P9) need two terminals or two machines on the same network. C++ socket starters use POSIX sockets, so build them on the Linux lab machines. Packet Tracer and Wireshark steps (P2, P5, P8) are checked by pasting the device or capture output.

Practical 1 · Unit I · CO1

Line encoding program

Aim: Write a program in Java or C++ to implement Unipolar NRZ, Polar NRZ, NRZ Inverted, Bipolar (AMI), Manchester and Differential Manchester encoding.

Specification

Input

One bit string per line, until end of file.

Output

Six lines per input, in this order. Each bit becomes two half-bit levels written as +, 0 or -.

Rules

  • Unipolar NRZ: 1 → ++, 0 → 00
  • Polar NRZ-L: 1 → ++, 0 → --
  • NRZ-I: start at -, invert on every 1
  • AMI: 0 → 00, 1s alternate starting with ++
  • Manchester (IEEE 802.3): 0 → +-, 1 → -+
  • Differential Manchester: previous level +; 0 = transition at bit start, 1 = none; always a mid-bit transition

Example

0110
UNIPOLAR 00++++00
NRZ-L --++++--
NRZ-I --++----
AMI 00++--00
MANCHESTER +--+-++-
DIFF-MANCHESTER -++--+-+

Specification · CRC

Input

Lines <char> <generator> <pos>. Data is the 8-bit ASCII code. pos is the codeword bit (1-based from the left) flipped by the channel, 0 for none.

Method

Append r zeros (r = generator length − 1), divide modulo 2, append the remainder. The receiver divides the received codeword.

Example

DATA 01001011
CRC 1001
CODEWORD 010010111001
RECEIVED 011010111001

Practical 4 · Unit II · CO2

Go-Back-N and Selective Repeat program

Aim: Write a program to simulate the Go-Back-N and Selective Repeat modes of the sliding window protocol.

Specification

Input

Lines <GBN|SR> <N> <frames> [lost frames…]. A listed frame is lost on its first transmission only.

Rounds

GBN: send every frame in the window (SEND i, or RESEND i if sent before). Walk the window in order: ACK i; at the first loss print LOST i and DISCARD every later frame in the round. Then TIMEOUT k and slide base to k, or to the window end if nothing was lost.

SR: send only the frames in the window not yet acked. Each frame is ACK i or LOST i. Then TIMEOUT i for each lost frame. Slide base past every acked frame.

Finish with TOTAL <transmissions>.

Example

GBN 3 5 1
SEND 0
SEND 1
SEND 2
ACK 0
LOST 1
DISCARD 2
TIMEOUT 1
RESEND 1
RESEND 2
SEND 3
ACK 1
ACK 2
ACK 3
SEND 4
ACK 4
TOTAL 7

Practical 6 · Unit V · CO5

TCP Berkeley socket programs

Aim: Using TCP socket primitives, write a client and server for (a) saying hello, (b) file transfer, (c) arithmetic calculator and (d) trigonometric calculator. Capture the traffic in Wireshark.

Protocol

Commands (client → server, one line each)

HELLO <name>       → HELLO <name>, I am the server
CALC <a> <op> <b>   → RESULT %.2f   | ERROR divide by zero
TRIG <fn> <deg>    → RESULT %.4f   | ERROR undefined
FILE <name> <size> → (then size raw bytes) OK <size> <checksum>
BYE                → BYE

Rules

  • a, b are integers; op is + - * / %; / is real division.
  • fn is sin, cos or tan of an angle in degrees; tan is undefined when |cos| < 1e-9.
  • checksum = sum of all file bytes (unsigned) mod 65536.
  • The client reads commands from stdin, prints SERVER: <reply> for each, and for FILE <path> first prints SENT <size> <checksum>.
  • Java: format numbers with Locale.ROOT so a comma never appears.

Practical 7 · Unit V · CO5
UDP file transfer program

  
Aim: Using UDP sockets, transfer a script, a text, an audio and a video file between two machines, and analyse the datagrams in Wireshark.

  

    
Protocol

    
  • Each datagram = 4-byte sequence number (big-endian) + up to chunk bytes of the file.
    • 
      
  • After the last chunk the sender sends an END datagram: sequence −1 (0xFFFFFFFF) followed by the 4-byte packet count.
    • 
      
  • The receiver stops at END or after 5 s of silence and writes the chunks in sequence order.
    • 
      
  • checksum = sum of all file bytes (unsigned) mod 65536.

      
Output
sender:   SENT <packets> <bytes> <checksum>
receiver: RECEIVED <packets> <bytes> <checksum> MISSING <seqs|none>
